# Chip & Cell 확장 — 시각화·고유 데이터 설계 스펙

날짜: 2026-09-01 · 상태: 사용자 승인 완료(채팅) · 선행 스펙: `2026-08-30-chipandcell-design.md`

## 배경

런칭(8/30) 후 사이트는 텍스트와 수치표만으로 구성되어 있다. AdSense 재도전과 무관하게, 이 사이트의 존재 이유는 "영어권에서 구할 수 없는 한국 반도체·배터리 정보"이므로 **다른 곳에서 조립되지 않는 데이터**를 쌓고 보여주는 것이 핵심 과제다. 사용자 방향 확정: 차트·그래픽·지속적 분석 기록을 더하되, **매매 권장 사이트가 아닌 정보 사이트**로서의 성격을 유지한다.

### 설계를 가른 실측 사실 (2026-08-31~09-01 확인)

| 사실 | 확인 방법 | 설계 영향 |
|---|---|---|
| `kis_api.get_investor_trend()`는 **30거래일치**(2026-07-20~)를 반환하나 래퍼가 `items[0]`만 사용 | 미니에서 API 직접 호출, `rows: 30` | 수급 이력 **30일 즉시 백필 가능** → 1일차부터 차트·검증이 의미를 가짐 |
| 그 외 기간의 수급은 소급 불가 | 위 API가 30행 한정 | **오늘 시작하지 않으면 영구 손실** → Phase 1 최우선 |
| 주가는 fdr로 언제든 복원 | 기존 파이프라인 | 가격 이력은 저장하지 않음(스냅샷 시점 종가만 기록) |
| `blog_visuals.candle_svg()`는 fdr만 쓰는 **순수 파이썬 인라인 SVG** 생성기 | 미니 소스 확인(의존성 `import requests`뿐, Chrome/mplfinance 무관) | 이식만으로 캔들차트 확보 |
| 미니 정규 배치 8/31 18:10 무인 완주 | `logs/daily_20260831.log` | 기존 파이프라인 위에 단계를 얹는 것이 안전 |

## 결정 사항 (브레인스토밍 확정)

1. **기록 형태** = 기계 장부 + LLM 노트 병행 (기계 장부만/LLM 노트만 기각)
2. **밸류체인 깊이** = 역할 계층도 + 검증된 관계선 소수 (계층도만/전면 납품관계 맵 기각)
3. **저장 방식** = 리포 내 JSON (SQLite·외부 서비스 기각) — 규모가 작고, **git 커밋이 기록 시점의 증명**이 되어 사후검증의 신뢰 기반이 됨
4. **검증 지평** = 20거래일 (스크리너 프로젝트들의 전향 검증 관행과 일치)
5. **로고** = 도입하지 않음 (상표·유지보수 부담 대비 효익 없음)

## 정직성 규칙 (정보 사이트 성격상 최우선)

- **백필과 실시간 관찰을 구분한다.** 수급·가격은 객관적 사실이라 소급 계산이 정당하지만, "그때 우리가 무엇을 봤는지"는 소급할 수 없다. 백필 구간 스냅샷에는 `backfilled: true`를 달고 화면에도 소급 계산임을 명시한다. LLM 관찰 노트는 오늘 이후 생성분만 존재한다.
- **검증 결과는 유리하든 불리하든 그대로 표시한다.** 선별 표시·사후 삭제 금지.
- **예측·목표가·매수/매도 언어 금지**(기존 규칙 승계). 장부는 "관찰의 기록"이지 "콜"이 아니다.
- **밸류체인 관계선은 공개 자료로 확인된 것만** 넣는다. 각 관계는 출처 URL과 연도를 필수 필드로 갖고, 근거를 찾지 못하면 포함하지 않는다.
- **시각화는 데이터 오류를 증폭한다.** 모든 차트에 기존 스테일 가드를 적용한다(데이터가 최신이 아니면 미생성 또는 날짜 명시).

## 데이터 계층

리포 내 `site/src/data/history/`에 둔다. 규모 추정: 수급 연 ~270KB, 장부 연 ~1.4MB. 단일 파일로 시작하고, 연도 경계에서 `-YYYY` 접미 파일로 분할한다(그 전까지는 분할하지 않음).

### `history/flows.json`

```json
{
  "updated": "2026-09-01",
  "flows": {
    "005930": {
      "2026-08-31": { "f": -2293, "i": -2349842, "p": 2352135 }
    }
  }
}
```

`f`/`i`/`p` = 외국인·기관·개인 순매수 수량(주). 최초 실행 시 종목별 30거래일 백필, 이후 매일 append. 같은 날짜 재실행은 덮어쓰되 파일 구조는 변하지 않는다(멱등).

### `history/ledger.json`

```json
{
  "updated": "2026-09-01",
  "records": [
    {
      "code": "005930",
      "date": "2026-08-31",
      "close": 257000,
      "pos52": 64.2,
      "vs_ma20": 1.8,
      "vs_ma60": -3.1,
      "r20": 24.15,
      "flow5_f": -1234567,
      "flow5_i": 234567,
      "backfilled": false,
      "note": null,
      "note_post": null,
      "verified": null
    }
  ]
}
```

- `vs_ma20`/`vs_ma60`: 종가의 이동평균 대비 괴리율(%).
- `flow5_f`/`flow5_i`: 해당 일자까지 5거래일 누적 외국인·기관 순매수. `flows.json`에 5일치가 없으면 `null`.
- `note`: LLM 관찰 1~3문장(심층 글을 쓴 종목·날짜에만). `note_post`: 해당 글 slug.
- `verified`: D+20 도달 전 `null`, 도달 시 `{"date": "...", "close": 271000, "return_pct": 5.45, "trading_days": 20}`.
- 거래일 계산에 별도 캘린더를 두지 않는다. `verify_ledger`가 fdr 가격 시계열에서 기록일 **이후 거래일 수를 세어** 20개 이상이면 20번째 거래일 종가로 채운다(휴장일 자동 처리).
- 같은 (code, date) 중복 기록 금지(멱등).

**백필 범위와 과거 시점 계산.** 장부도 수급과 같은 30거래일 구간을 백필한다(그래야 D+20 검증 결과가 1일차부터 나온다). 백필 레코드의 지표는 **그 날짜 기준으로 계산해야** 하므로, `metrics.compute()`에 "특정 일자까지만 사용" 옵션을 더해 시계열을 해당 일자까지 잘라 계산한다(오늘 기준 값을 과거 레코드에 넣으면 미래 정보 누출이자 사실 오류다). 검증은 백필 레코드에도 동일하게 적용된다.

**백필 레코드는 git 증명을 갖지 못한다.** 커밋 시점이 관찰 시점보다 늦기 때문이며, 이것이 `backfilled: true` 표기가 필요한 이유다. 실시간 축적 레코드만 "기록 시점이 커밋으로 증명되는" 기록이다.

## 컴포넌트

| 파일 | 책임 |
|---|---|
| `pipeline/flow_history.py` | KIS 30행 응답을 받아 `flows.json` 백필·append. 토큰 실패 시 no-op(기존 배치 중단 금지) |
| `pipeline/record_ledger.py` | 매일 27종목 스냅샷 append(멱등). 최초 실행 시 30거래일 백필(`backfilled: true`, 과거 시점 기준 계산) |
| `pipeline/metrics.py` (수정) | `compute(df, asof=None)` — `asof` 지정 시 그 일자까지만 사용해 과거 시점 지표를 계산 |
| `pipeline/verify_ledger.py` | 미검증 레코드 중 D+20 도달분에 실제 결과 기입 |
| `pipeline/charts.py` | `candle_svg`(이식·테마 대응)·`flow_bar_svg`·`sector_scatter_svg`. 산출물 `site/src/data/charts/*.svg` |
| `pipeline/valuechain.py` | 단계 분류 SSOT + 검증된 관계선(출처·연도 필수) |
| `site/src/components/ValueChain.astro` | 계층도 SVG 렌더 + 노드에 라이브 데이터 |
| `site/src/components/TrackRecord.astro` | 종목별 장부·검증 결과 표 |

`gen_deep_dive.py`는 글 생성 시 관찰 노트를 함께 산출해 장부에 기록하도록 확장한다.

### 차트 상세

- **캔들(종목, 60일)**: `blog_visuals.candle_svg` 이식. 색상 하드코딩을 CSS 변수(`var(--up)`/`var(--down)`)와 `currentColor`로 교체해 라이트/다크 모두 대응. 인라인 삽입이므로 페이지 CSS를 그대로 상속한다.
- **수급 바(종목, 30일)**: 외국인·기관 일별 순매수 양음 바.
- **로테이션 산점도(섹터)**: x=60일 수익률, y=20일 수익률. 각 종목 점 + 이름.
- Astro는 `?raw`로 SVG 문자열을 가져와 `set:html`로 인라인 삽입한다(외부 요청 0, JS 0 — 크롤러·AI 답변엔진이 차트 내용을 그대로 읽는다).
- 데이터가 스테일이면 차트를 생성하지 않고, 페이지는 차트 영역을 생략한다.

### 밸류체인

반도체는 메모리 제조 / 장비 / 소재 / 후공정·테스트, 배터리는 셀 / 양극재 / 부소재·장비로 분류한다. 각 종목의 단계 배정은 구현 시 공개 자료(사업보고서·회사 IR)로 확인한다. 관계선은 `{"from","to","label","source","year"}` 구조를 갖고 **근거가 확인된 것만** 포함하며, 하나도 확인되지 않으면 계층도만 렌더한다. 새 URL을 만들지 않고 기존 섹터 페이지 상단에 배치한다.

## 파이프라인 통합

`run_daily.sh` 순서를 확장한다:

```
export_data → flow_history → record_ledger → verify_ledger → charts
            → gen_deep_dive → gen_weekly → commit → push
```

`export_data` 실패는 기존대로 배치를 중단시킨다(데이터 없이 진행 불가). 그 외 신규 단계는 **실패해도 후속 단계를 막지 않는다** — 수급 이력이 하루 빠지는 것보다 글 발행과 데이터 갱신이 멈추는 쪽이 나쁘다. 각 단계는 실패를 로그에 남긴다(텔레그램 발송 금지 규칙 승계).

## 테스트

순수 함수 단위 테스트를 우선한다: 거래일 수 세기와 D+20 종가 선택, 5거래일 누적 수급(결측 시 `null`), 장부 append 멱등성(같은 날 2회 실행 시 중복 0), 백필 플래그 부여, SVG 생성기(유효한 `<svg>` 루트 반환·10봉 미만 입력 시 빈 문자열). 라이브 실증은 완료 규칙에 따라 실제 실행·라이브 URL 확인으로 수행한다.

## 단계

1. **Phase 1 (시간 임계, 최우선)**: `flow_history` 30일 백필 + 일일 축적, `record_ledger` 시작, `verify_ledger`. 화면 노출 없이 데이터부터 쌓는다.
2. **Phase 2**: 캔들·수급 차트 → 종목 페이지.
3. **Phase 3**: 밸류체인 계층도 → 섹터 페이지.
4. **Phase 4**: Track record 섹션(검증 결과 포함) → 종목 페이지.

## 비목표 (YAGNI)

회사 로고, 예측·목표가, 별도 DB(SQLite·외부 서비스), 자바스크립트 차트 라이브러리, 신규 URL 추가, DART 공시 통합(후속 과제), 전체 기록 열람용 `/record/` 페이지(종목 페이지 섹션으로 충분한지 본 뒤 판단).
